# План: внешний API DeepSeek для помощника «Разбор» с переключением провайдера

## Цель
Дать возможность выбирать, через какой AI разбирает текст помощник «Разбор»:
- **Lovable AI** (как сейчас, модель openai/gpt-5.6-sol) — работает без ключа, по кредитам Lovable;
- **DeepSeek** (deepseek-chat) — через ваш оплаченный аккаунт DeepSeek, расходы идут на него, а не на кредиты Lovable.

Переключение нужно и чтобы снизить расходы (у вас уже оплачен DeepSeek), и чтобы сравнить качество разбора разными моделями.

## Что увидит пользователь
1. В «Настройках» появится блок **«AI-провайдер»**: выбор «Lovable AI» или «DeepSeek». По умолчанию — Lovable (ничего не сломается, пока ключ не добавлен).
2. Под переключателем — подсказка: для DeepSeek нужен один раз добавленный ключ (добавляю я, через секреты проекта, в браузере он не виден).
3. В панели «Разбор» рядом с кнопкой анализа — маленькая подпись, какой провайдер сейчас используется, чтобы сравнение качества было осознанным.
4. Если выбран DeepSeek, но ключ не добавлен или API вернул ошибку — понятное сообщение об ошибке с предложением переключиться обратно на Lovable. Автоматического молчаливого переключения нет — пользователь всегда знает, кто отвечал.

## Как это работает

```text
BraindumpPanel (текст/голос)
        │  передаёт текст + выбранный провайдер
        ▼
Edge Function parse-braindump
        │  router по параметру provider:
        ├── "lovable" → Lovable AI Gateway (openai/gpt-5.6-sol, Responses API)
        └── "deepseek" → https://api.deepseek.com/chat/completions
                         (модель deepseek-chat, ключ из секрета DEEPSEEK_API_KEY)
        ▼
Единый формат ответа (task/project/recurring/not-task) → BraindumpPanel
```

## Технические детали
- **Секрет**: запросить у пользователя ключ DeepSeek один раз через `add_secret` (имя `DEEPSEEK_API_KEY`). Ключ только на сервере.
- **`supabase/functions/parse-braindump/index.ts`**: 
  - принять новый параметр `provider` ("lovable" | "deepseek"), по умолчанию "lovable";
  - вынести промпт и парсинг ответа в общий код, добавить ветку вызова DeepSeek API (OpenAI-совместимый chat/completions, `response_format: json_object`, без таймаутов);
  - нормализовать ответ DeepSeek в тот же JSON-формат, что и сейчас (до 12 карточек, типы, даты);
  - ошибки DeepSeek (неверный ключ, недостаточно средств, rate limit) возвращать с понятным текстом; фронт показывает их как есть.
- **`BraindumpPanel.tsx`**: читать выбранный провайдер из localStorage, передавать в вызов функции, показывать активный провайдер мелким текстом.
- **`SettingsModal.tsx`**: переключатель провайдера (две опции), сохранение в localStorage.
- Ничего в текущей ветке Lovable AI не ломается: без ключа DeepSeek приложение ведёт себя ровно как сейчас.

## Проверка
1. С ключом DeepSeek: прогнать реальный пример текста через обе ветки (Lovable и DeepSeek) и сравнить результат разбора.
2. Без ключа: выбор DeepSeek даёт понятную ошибку, переключение обратно на Lovable работает.
3. `tsc`/сборка зелёные.
