# План: подключение своего API-ключа (DeepSeek, OpenRouter, OpenAI, Groq, Mistral, локальные модели)

## Мелкая правка интерфейса (добавить в этот же PR)
- В `src/components/ProjectsPanel.tsx` строка-ссылка «Повторяющиеся задачи» должна стать кликабельной кнопкой с иконкой `Repeat` (та же, что в боковом меню) и переключать пользователя на вкладку «Повторяющиеся задачи» (`templates`).
- Текст останется понятным: «Если нужно повторение по расписанию — это <иконка> Повторяющиеся задачи».

## Что получит пользователь
1. В «Настройках» — новый блок **«Свой ИИ-ключ»**: поле для ключа, кнопка «Проверить», кнопка «Удалить ключ».
2. Вставили ключ → приложение само определяет сервис (по виду ключа и проверочным запросам), показывает его название и подгружает список доступных моделей.
3. Выпадающий список моделей, выбранная модель сохраняется.
4. Пока ключа нет — всё работает как сейчас, на встроенном ИИ Lovable. Свой ключ — апгрейд, не обязанность.
5. Ошибки простым языком: «ключ неверный», «на ключе закончились средства», «слишком много запросов», «сервис недоступен», «выбранная модель недоступна».
6. Подпись в панели «Разбор»: какой сервис и модель сейчас отвечают.

## Где хранится ключ
Только в браузере устройства (localStorage). На сервер он не сохраняется никогда: при работе со своим ключом запрос к провайдеру идёт **напрямую из браузера**, минуя наш backend. Встроенный режим по-прежнему идёт через Edge Function, где лежит серверный ключ Lovable.

```text
Свой ключ:      Браузер ──► api.deepseek.com / openrouter.ai / api.openai.com ...
Встроенный:     Браузер ──► Edge Function ──► Lovable AI Gateway
```

## Определение сервиса
Реестр провайдеров — один массив с полями: id, название, базовый URL, префикс ключа, путь списка моделей, поддержка json_schema. Добавить новый сервис = одна запись в массиве.

| Сервис | Признак ключа | Базовый URL |
|---|---|---|
| OpenRouter | `sk-or-` | https://openrouter.ai/api/v1 |
| OpenAI | `sk-proj-` / `sk-` | https://api.openai.com/v1 |
| DeepSeek | `sk-` (32 hex) | https://api.deepseek.com/v1 |
| Groq | `gsk_` | https://api.groq.com/openai/v1 |
| Mistral | прочее | https://api.mistral.ai/v1 |
| Google (OpenAI-совместимый) | `AIza` | generativelanguage.googleapis.com/v1beta/openai |
| Своя / локальная | пользователь указывает URL вручную (необязательное поле) | любой |

Проверка: по префиксу выбираются кандидаты, к каждому по очереди делается запрос `GET /models`. Первый ответ 200 определяет сервис и сразу даёт список моделей. Все они — OpenAI-совместимые, поэтому единый код запроса.

## Устойчивость к слабым моделям
Слабые модели плохо держат json_schema. Поэтому:
1. Запрос: сначала `response_format: json_schema` (если провайдер поддерживает), при ошибке 400 — повтор с `json_object`, при повторной ошибке — без формата.
2. Разбор ответа: снять markdown-обёртку ```json, вырезать первый сбалансированный JSON-объект из текста, при неудаче — одна попытка ремонта (обрезка хвоста).
3. Валидация каждой карточки: неизвестный kind → task, категория вне 0-5 → 0, кривая дата → null, пустой текст → карточка отбрасывается, лимит 12.
4. Если после всего валидных карточек нет — честное сообщение «Модель не справилась с форматом, попробуйте другую модель», а не мусор в карточках.

## Проверка (критерии приёмки)
1. Ключ DeepSeek и ключ OpenRouter определяются без ручного ввода адреса, список моделей подгружается.
2. Выбранная модель применяется и в «Разборе», и в подсказке шагов.
3. Оба сценария проверяются вживую минимум на двух моделях от разных сервисов.
4. Удаление ключа возвращает встроенный режим, проверяется тем же прогоном.
5. Ошибочный ключ даёт «Ключ неверный», а не белый экран.
6. Типы и сборка зелёные.

## Гибкие повторяющиеся задачи (в этот же заход)
Сейчас правило хранится как `recurrence` (daily/weekly/monthly) + один `recurrenceDay` + `recurrenceHour`, то есть «каждую неделю в один день». Расширяем:

- **Несколько дней недели**: новое поле `recurrenceDays: number[]` (например пн+ср+пт). Старое `recurrenceDay` продолжает читаться — миграция без потерь.
- **Интервал**: `recurrenceInterval` — «каждые N дней/недель/месяцев» (каждые 2 недели и т.п.).
- **Каждый будний / каждые выходные** — быстрые пресеты, которые просто заполняют `recurrenceDays`.
- **Последний день месяца** для monthly (`recurrenceDay = -1`).
- **Дата окончания / без окончания** — необязательное поле `until`.

Правки: `src/types.ts` (поля), `src/lib/recurring.ts` (`nextOccurrence` учитывает набор дней, интервал, последний день месяца и `until`), `src/components/TemplatesPanel.tsx` и форма повторения в `QuickAddBar`/`AddTaskModal` — компактный редактор правила с пресетами («каждый день», «по будням», «выбранные дни недели», «каждые N недель», «раз в месяц») и человекочитаемой подписью типа «каждый пн, ср в 9:00».

Проверка: для каждого типа правила проверяю расчёт следующей даты и создание следующего экземпляра после отметки «готово».
